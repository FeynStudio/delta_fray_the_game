2. New line in section 9, after the "No-comments guard (T-023)" line:
- Format-string guard (T-036): scripts/guards.sh prints GUARD FAIL [format-string-literal]: First argument of console.* and util.format must be a fixed string; use '%s' and pass the value after it, then one path:line:text per hit, and fails, when a console.log, console.error, console.warn, console.info or util.format call in a .js or .mjs file at any depth in scripts/, tests/, sim/, src/ or agent-team/evidence/ (node_modules skipped) does not start with a fixed string. Passes: a single- or double-quoted literal followed by , or ), a template literal with no ${ followed by , or ), an empty call; later arguments are not checked, so console.log('%s', a + b) passes. Hits: anything else as the first argument (identifier, member, call, number, parenthesised expression), a literal followed by anything other than , or ) (+, .concat, ?, or the end of the line), a template literal with ${ or one that does not close on the line, and a ( that ends the line. One grep -E over lines, so it does not see aliases (const p = console.log), computed members (console['log'], console[method]), a space before the dot (console .log), console?.log, format imported from node:util and called bare, other file types (.cjs, .ts, .html), or a quoted string continued onto the next line with a trailing backslash. A matching text inside a string or a comment is reported too (a false hit, never a missed one). Stricter than the CI semgrep rule unsafe-formatstring (a template literal with ${ as the only argument is a hit here). Fix: put '%s' first and pass the value after it, as sim/balance.mjs does since T-036.
