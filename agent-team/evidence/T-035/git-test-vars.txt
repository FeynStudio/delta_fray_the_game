- The installed git, git version 2.56.0.windows.4 on Windows 11: the GIT_TEST_ names compiled into git.exe (git --exec-path, read as bytes by git-test-vars.mjs; 48 names, all probed below). rev-list, diff-tree, log, rev-parse and branch, the only commands the module runs, are built into git.exe.

No other installed document names a GIT_TEST_ variable that the probe covers.
- Not read: git's source (commit-graph.c, commit.c, replace-object.c, promisor-remote.c) and t/README. They are not installed and the brief allows no network code; the verdicts below rest on the probe, not on reading the source.

What was run (agent-team/evidence/T-035/git-test-vars.mjs <ref>; fixtures and the scratch folder only in the OS temp dir, empty global config, GIT_CONFIG_NOSYSTEM=1)
- Four parent sources the module turns off, each in its own fixture (A code, H Handoff naming A, B code, C revert to A = true latest code commit, D agent-team/ only = HEAD), each shown live first (plain git follows it):
  commit-graph: forged single-file graph, D's parent set to H; module switch core.commitGraph=false.
  replace objects: refs/replace/<D> names a copy of D with parent H; module switch GIT_NO_REPLACE_OBJECTS=1.
  grafts: .git/info/grafts gives D the parent H; module switch GIT_GRAFT_FILE=<a file that does not exist>.
  lazy fetch: promisor remote whose upload-pack runs a marker command, HEAD's tree object removed; module switch GIT_NO_LAZY_FETCH=1.
- Each of the 48 variables set to 1, one at a time, in the caller's environment: plain git with the module's switch for that source (parent of D, or whether the marker ran), and checkHandoff of the module at the given ref. A variable "re-enables <source>" when plain git with the switch on follows the forged parent or runs the marker, or checkHandoff gives the stale PASS naming A.
- GIT_TEST_FSMONITOR also set to a marker command (a command source, not a parent source) in a fixture without a promisor remote.

- GIT_TEST_PROTOCOL_VERSION, GIT_TEST_SIDEBAND_ALL: does not touch a parent source (transport; the lazy-fetch marker does not run with GIT_NO_LAZY_FETCH=1).

The two SKIP routes (GIT_TEST_ASSUME_DIFFERENT_OWNER, GIT_TEST_COMMIT_GRAPH_DIE_ON_PARSE) turn a stale Handoff into SKIP, not PASS; they belong to the SKIP-on-git-error design (out of scope) and are listed in the Handoff's Follow-ups.
