- Syntax check for sim/ (T-026, T-038): tests/syntax-check.test.js runs `node --check` on every .js and .mjs file under sim/ in every verify.sh run (any --feature) and so in CI on pull requests, because verify.sh's lint step covers only src/*.js, tests/*.js and scripts/*.mjs and does not cover sim/; before it, a syntax error in sim/balance.mjs failed only --feature balance and --feature all. Two functions in the test file: codeFiles(dir) walks the folder on disk with no git call (any depth, untracked files too, folders named node_modules skipped, symbolic links and junctions not followed) and checkSyntax(base, dir) starts Node itself for each file found, execFileSync(process.execPath, ['--check', <absolute path>]) with no shell, and returns { checked, errors } with paths relative to base and forward slashes, each error as `path: Node's message`; a folder with no .js or .mjs file is an error (`sim: no .js or .mjs file found`) and a missing folder throws. Every control character except the line feed (U+0000 to U+0009, U+000B to U+001F, U+007F to U+009F) is removed from the reported paths and from Node's message by plain() before they go into a line, so escape, bell and backspace bytes from a failing source line do not reach the test output or the verify logs (T-038). The test 'every .js and .mjs file under sim/ passes node --check' prints one reporter line `node --check ran on <path>` per file; a second test proves both functions on a throw-away folder made under resolve(os.tmpdir()), so a relative TEMP, TMP or TMPDIR value such as one starting with a dash cannot turn the fixture path into a Node option, with a package.json holding {"type":"module"} at its root so its .js files are parsed under the repo's module rule (sim/deep/top-return.js holds `return;`, a syntax error only as a module), and removes it (T-038). Three more tests (T-038): plain() on a string; a fixture whose failing line holds ESC [31m, BEL, BS and U+009B is reported by name with SyntaxError and none of those code points; a folder junction under the fixture's sim/ that points to a broken .mjs outside it is neither checked nor reported, while the target folder itself is. Not checked here: other file types (.cjs, .ts, .json), evidence scripts, .sh files, index.html, hard links, a linked sim/ folder and a link to a file (on Windows a file link needs a special right). Absolute paths can still appear in a failure message (BACKLOG 26d). The files are only parsed, never run or imported (sim/balance.mjs plays 2000 games and calls process.exit).
