## Goal
`node scripts/count-leftovers.mjs` always runs Windows' own tasklist at C:\Windows\System32\tasklist.exe, so a tasklist.exe in the folder it is run from (or earlier on PATH) can no longer run in its place, and FEATURE_MAP states the new known limit.

## Context
BACKLOG line, as logged (agent-team/BACKLOG.md line 171), verbatim:
"Make scripts/count-leftovers.mjs call tasklist by its full path C:\Windows\System32\tasklist.exe, so a tasklist.exe in the current folder cannot run in its place when NoDefaultCurrentDirectoryInExePath is unset, and add "current folder" to the FEATURE_MAP known-limits line (T-052 security review round 1, Issue 1, 2026-11-25; phase 1)."

Source: agent-team/tasks/T-052.md, Security review round 1, Issue 1: "The literal command 'tasklist' is looked up by Node's process launcher, which searches the current folder before PATH unless the environment variable NoDefaultCurrentDirectoryInExePath is set. My probe confirmed it: with the variable unset, a tasklist.exe in the current folder ran instead of System32's. ... Possible fix in a later brief: use the literal 'C:\\Windows\\System32\\tasklist.exe', which T-049's literal rule would accept, or at least add "current folder" to the FEATURE_MAP limit line."
