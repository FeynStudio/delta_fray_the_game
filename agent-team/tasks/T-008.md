## Goal
The reviewer can see the power gauge, the forward direction dial and the backward direction dial in screenshots that `verify.sh --feature input` saves, instead of the single post-launch screenshot that shows no gauge.

## Context
Request from the human, pasted as-is:
"review next 5 items to build based on product-a's plan and create briefs"

- Not a docs/PLAN.md game feature. It is the open harness item in agent-team/BACKLOG.md (T-002, logged 2026-11-08): scripts/smoke.mjs takes the input screenshot after the second Space, when the phase is 'moving' and drawGauge draws nothing, so input-smoke.png cannot show a gauge or prove that no path or end-point marker is drawn. It is also the REPEATS row "smoke screenshot cannot show the feature under review (taken in the wrong phase)" (T-002).
- What exists now (read scripts/smoke.mjs): `FEATURES.input` runs `inputProbe` in one page and calls `shots.push(await a.screenshot())` after it. Main writes only `shots[0]` as `<out>.png`. The gauges sweep in real time in the browser, so a screenshot taken inside the checked page between `setGauge` and `press` could shift the power or needle reading and break the existing checks.
- Harness contract: FEATURE_MAP section 9 ("changing it needs a brief"; "Smoke checks save a screenshot next to their output in agent-team/evidence/T-###/ for the reviewer"). expected/input-smoke.json is the spec and stays byte-for-byte unchanged.
