## Coordinator choices (technical, not human decisions)
- Files (all comment-free; no shebang needed, it is run with `node`):
  - scripts/count-leftovers.mjs (new). Imports only from node:child_process (`execFileSync`), node:fs (`readdirSync`), node:os (`tmpdir`), node:path (`resolve`) and node:url (`pathToFileURL`). Exports:
    - `MARK` = 'galaxy-smoke-' and `IMAGES` = ['chrome.exe', 'msedge.exe'] (the two browsers findBrowser can pick on Windows).
    - `parseWait(args)`: args is the argument list after the script name. No argument gives 0; one argument made only of the digits 0 to 9, value 0 to 120, gives that number; anything else (a second argument, a sign, a decimal point, a letter, an empty string, more than 120) gives null.
    - `countFolders(dir)`: the number of entries directly in dir whose name starts with MARK, exact case (files and links counted too, as in T-040; nothing is opened or followed). Throws when dir cannot be read.
    - `countImage(listing, image)`: the number of lines of a tasklist CSV listing (CRLF or LF) that start with `"<image>",`, exact case. A line `INFO: ...` (no match) and every other image give 0.
    - `formatCounts({ at, wait, folders, processes })`: the one output line, `counted <at as ISO time> after waiting <wait> s: galaxy-smoke-* folders in the OS temp dir <folders>; chrome.exe processes <n>; msedge.exe processes <n>`, where processes is `{ 'chrome.exe': n, 'msedge.exe': n }` or null, and null prints `processes not counted (not Windows)` in place of the two process counts.
  - Run directly (the isMain pattern of scripts/home-paths.mjs; importing runs nothing): a null parseWait prints `usage: node scripts/count-leftovers.mjs [seconds 0-120]` and exits 2; otherwise it waits that many seconds, counts the folders in `resolve(tmpdir())`, and on Windows (process.platform 'win32') runs, once per image, `execFileSync('tasklist', ['/FI', 'IMAGENAME eq ' + image, '/NH', '/FO', 'CSV'], { encoding: 'utf8', windowsHide: true, stdio: ['ignore', 'pipe', 'ignore'] })`, then prints the formatCounts line and exits 0. If tasklist or the folder read throws, it prints only `count-leftovers: count failed (<error code, or "unknown">)` and exits 1: no message text, no path, no stack trace. Every print uses process.stdout.write (no console call).
  - tests/count-leftovers.test.js (new): ROOT as in tests/home-paths.test.js; the cases of Done-when 4. It never runs tasklist (CI runs on Linux and the count of real processes is not a stable fixture); the one run-directly case passes a bad argument, so the script stops at the usage line before counting.
- What it never does: end, signal or open a process; read a process command line, path, user, window title, module or service list (no tasklist `/V`, `/M`, `/SVC`, no `/PID` filter, no WMIC, PowerShell, `wmic` or `Get-Process`); print a path, a process id or the temp-dir name; take an image name, a folder or a command from its arguments or the environment (the only argument is the wait); use a shell, exec, execSync, spawn or a template literal or variable as the command.
- Why a child process at all: Node has no built-in API that lists processes on Windows, and the T-040 counter, read by the T-040 security reviewer, already does it this way. `tasklist` is found through PATH as in T-040 (T-049's rule accepts a string-literal command; a full System32 path would need the environment and would not be a literal). Known limit, said in the Handoff and FEATURE_MAP: whoever can put a `tasklist` program earlier on PATH can make the counts wrong; they could already change the machine in worse ways.
- Size: the two new files together 150 added lines or fewer.
