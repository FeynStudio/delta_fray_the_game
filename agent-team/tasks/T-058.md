## Coordinator choices (technical, not human decisions)
- Fix by ignore rule, not by moving output: `git worktree remove` refuses only on modified tracked files and untracked files that are not ignored (it checks with `git status --porcelain`, which lists no ignored files), and deletes ignored files with the folder. A tracked rule in a new root .gitignore that ignores agent-team/evidence/<task>-review/ therefore lets the unchanged reviewer.md command succeed. This reasoning is from git's documented behaviour and is not yet run; Done-when 3 and 5 prove it.
- Rule shape: anchored to the evidence folder and to the reviewer's suffix only, so it ignores agent-team/evidence/T-049-review/ and agent-team/evidence/T-051-review/ and does not ignore agent-team/evidence/T-049/, agent-team/evidence/T-049/before/ or any owner label. Exact pattern is the owner's, for example `/agent-team/evidence/T-[0-9]*-review/`.
- The tracked .gitignore holds only the new rule (no header comment is required; .gitignore is not a code file, but keep it minimal). It does not copy the human's untracked line `agent-team/BACKLOG samples.md`; that local file is the human's.
- The new test reuses gitEnv from scripts/handoff-check.mjs for every git call (the paved road for git in tests), runs git only as `execFileSync('git', [array literal], options)` with no shell, and never prints an absolute path: on Windows the OS temp dir sits under the home folder, and a temp path in a failing message would land in a verify log and trip the home-path guard (FEATURE_MAP line 95).
