### Item 3: format-string guard (scripts/guards.sh)
- A new check in guards.sh, added before `exit $FAIL`. Existing lines stay byte for byte; added lines only.
  - On a hit it prints `GUARD FAIL [format-string-literal]: <one-line message, for example "First argument of console.* and util.format must be a fixed string; use '%s' and pass the value after it">`, then one path:line:text per hit, and sets FAIL=1 (the guard() style).
  - Plain grep -E or bash only; no new tool and no node helper file.
- Calls checked: console.log, console.error, console.warn, console.info and util.format.
- Files checked:
  - .js and .mjs at any depth in scripts/, tests/, sim/ and src/;
  - .mjs and .js at any depth in agent-team/evidence/. This widens the human's "evidence scripts" by .js, a coordinator choice: semgrep scans .js too, and the survey found no .js hit.
  - node_modules is skipped.
- Rule (the first argument must be a fixed string):
  - PASS:
    - a single- or double-quoted string literal not followed by `+`;
    - a template literal with no `${`;
    - an empty call `console.log()`.
  - HIT:
    - an identifier, member expression or call as the first argument;
    - a quoted literal followed by `+` (concatenation);
    - a template literal containing `${`;
    - an opening `(` that ends the line, because a line-based check cannot see the argument. The fix is to start the argument on the same line.
  - Later arguments are not checked: `console.log('%s', a + b)` passes.
- Known limits (disclosed, not built): aliases (`const p = console.log`), computed members (`console['log']`), `format` imported from node:util and called bare, and a string literal that itself contains a quote character followed by `+` on the same line. The owner names any further limit found.
- Existing hits from the survey (Done-when 3) are handled in this task, not allowlisted:
  - A non-literal call in a non-protected file is rewritten to `'%s'` plus the original expression, for example `console.log('%s', \`...\`)`. Output must stay byte-identical, shown by a before/after run.
  - Coordinator's expectation: one hit, sim/balance.mjs:77. It is seeded, so `node sim/balance.mjs --games 2000` stdout and its --out JSON can be compared byte for byte.
  - More than 5 hits in total, or any hit in a protected file: stop BLOCKED with the full list. The human then chooses between fixes and an explicit allowlist. No allowlist is built without the human.
- Ordering for the human: the sim/balance.mjs fix is committed on this branch. The proposed guards.sh fails on BASE master without it (Done-when 10 shows that). So the copied guards.sh goes in on top of this branch or after it is merged; apply-steps.txt says so.
