## Coordinator choices (technical, not human decisions)
How a request is answered after the change, in this order (fix list (a) to (e)):
1. Host (e): the Host header, lower-cased, must equal `127.0.0.1:<port>` or `localhost:<port>`, where <port> is the port the server really listens on (`server.address().port`, so it also holds for port 0). Anything else, a missing Host header included, gets 421 with the body `Misdirected request`. 421 rather than 403 because the request was meant for another host name; either would meet (e).
2. Encoded separators: a raw request path (before decoding) that holds `%2F` or `%5C` in either case gets 404. No page of the game asks for one.
3. Decoding: as today (`decodeURIComponent` of the URL pathname; 400 `Bad request` on a decode error). Only `/` itself maps to `/index.html`; any other path that ends in `/` gets 404.
4. Odd characters (b): a decoded path that holds a backslash, a colon, a `~`, a control character (U+0000 to U+001F, U+007F) or NUL gets 404, on every platform, so the tests give the same result on Linux CI.
5. Allow-list (a): the decoded path must be exactly `/index.html`, or match `^/src/(?:[A-Za-z0-9_-]+/)*[A-Za-z0-9_-]+\.js$` (JavaScript under src/, subfolders allowed, names of ASCII letters, digits, `_` and `-` only). Compared with exact case, so /INDEX.HTML and /SRC/game.js get 404. Everything else gets 404. This also refuses dot parts, `..`, trailing dots and spaces, and every file type the game does not load.
6. Names (c): every part of the path is checked lower-cased: none may start with `.`, equal `secrets`, or end with `.` or a space. (Redundant with step 5 on the request; it is the rule step 7 applies to the real path.)
7. Real path (d): the file is resolved with `fs.promises.realpath` (or `fs.realpathSync.native`), never the JavaScript `fs.realpathSync` or the callback `fs.realpath`. The real path of the root is taken the same way once in startServer, before it listens (startServer rejects if the root cannot be resolved). The real file path must be inside the real root (`path.relative` gives no `..` first part and no absolute path); its relative path, split on both `/` and `\`, must pass the step 6 rule, and, written with `/`, must itself pass the step 5 allow-list (so a link src/a.js that resolves to a file outside src/ is refused). Any failure, a realpath error included, gets 404.
8. Read: as today (`readFile` of the real path, 200 with the TYPES Content-Type and `Cache-Control: no-store`; 404 `Not found` on any read error).
- Unchanged: the export name and signature `startServer(root, port = 0, host = '127.0.0.1')`, the returned `{ url, close }` and the url form, the 127.0.0.1 listen address, the TYPES table, the 404 and 400 bodies, and the run-directly block (lines 57-63) byte for byte, so `npm run dev` and scripts/smoke.mjs need no change. Imports only from node: built-in modules; no dependency.
- Unit test (f): new tests/serve.test.js, the paved-road pattern (node:test, node:assert/strict). Each test builds its own throw-away root under `mkdtempSync(join(resolve(tmpdir()), 'serve-test-'))` holding fake files only (the bodies are fixed fake strings): index.html, src/game.js, src/config.js, src/sub/deep.js, src/longmodulename.js (so Windows makes an 8.3 name for it where 8.3 names are on), .env, .env.local, .gitignore, .git/config, secrets/x.txt, src/secrets/x.js, sub/s.txt, package.json, and a sibling folder outside/ holding o.txt and o.js next to the root inside the same temp parent. Links (folder links made with `symlinkSync(target, path, 'junction')`, which is a plain symlink outside Windows): root/link-out and root/src/link-out to outside/, root/link-secrets and root/src/link-secrets to root/secrets; a file symlink root/src/env.js to root/.env where the OS allows it (on Windows without the symlink right that one case is reported as skipped with its reason, never silently). It starts `startServer(root, 0)`, sends real HTTP requests to 127.0.0.1 with node:http (node:net for the request with no Host header), checks the status and that no refused request returns a fake body, closes the server, removes the links before the folder and the folder in `finally`. It covers at least one request of every kind in Done-when 3 and every allowed request. On Windows it also requests /ENV~1 and /src/LONGMO~1.JS and records with `t.diagnostic` whether the short name existed in the fixture (fixed text, yes or no). One test starts the server on a folder link that points to the fixture root and checks that the allowed files are still served and the bypass kinds still refused (the real root is taken from the link). No test message, assertion text or diagnostic holds an absolute path; failures name the request path and the status only.
