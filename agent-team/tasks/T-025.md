- The four fixes:
  1. Property named like a keyword. A word from REGEX_AFTER_WORD that directly follows a `.` (also `?.`, blanks between them allowed) is a property name, so a slash after it is division. `return`, `typeof`, `case` and the others as real keywords behave as today.
  2. One copy per directive. checkTree accepts each ALLOWED entry at most once per file; a second exact copy in the same file is a finding. So `node scripts/no-comments.mjs`, and with it ./scripts/guards.sh, exits 1 on a duplicate.
  3. Exact folder names. The old-evidence skip applies only to folders directly under agent-team/evidence/ whose name is exactly T-001 to T-014. T-001-old, T-014-new and T-0140 are checked.
  4. Tests pin the range: a comment in agent-team/evidence/T-001/ and in T-014/ is skipped; a comment in T-015/, T-014-new/, T-0140/ and T-001-old/ is reported.
- Not changed, on purpose: the folder rule itself (the human confirmed "every folder except T-001 to T-014" on 2026-11-12, answer 1), so a new script put into an old T-001 to T-014 folder is still skipped; the two ALLOWED entries and their exact texts (answer 5, "keep it strict"); the list of checked folders and file types; the command-line output format.
