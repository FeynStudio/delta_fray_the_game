Run directly, it checks the repo it lives in (the folder above scripts/), prints the report lines with `console.log('%s', line)` and exits with the code; importing it runs nothing (the isMain pattern of scripts/home-paths.mjs).

- Files checked: every file under `<root>/scripts/` and `<root>/tests/` at any depth whose extension, compared without letter case, is .js, .mjs or .cjs; found by walking the disk with no git call (untracked files too). Folders named exactly node_modules are skipped. A symbolic link or junction found under scripts/ or tests/ is not followed and is itself a finding (rule `link`), because verify.sh would run a linked test file and Node would import a linked module. Nothing else is skipped and there is no allowlist by path, apart from the one exception below.
- Rules, each a finding kind:
  - `import`: every child_process import is a static `import { ... } from 'node:child_process'` that names only spawn, spawnSync, execFile or execFileSync, with no `as` rename. A namespace or default import, the specifier without `node:`, `require(` of child_process, a dynamic `import(` of child_process, and importing exec, execSync, fork or any other name are findings.
  - `exec`: the text `exec(` or `execSync(`, blanks allowed before the bracket, outside string literals, where the word is not preceded by `.` or a name character, is a finding in any checked file, whether or not it imports child_process. A method call such as `/re/.exec(data)` (tests/serve.test.js line 121) is not a finding: it is a RegExp method, and every child_process import is a named one, so no object of child_process can be reached through a dot.
  - `command`: the first argument of every call of an imported name is a single- or double-quoted string literal, or exactly `process.execPath`. A template literal, a variable, a member other than process.execPath, or a call is a finding.
  - `shell`: an identifier or quoted key `shell` anywhere in the call's arguments (outside string literals) is a finding: `shell: true`, `shell: false`, `'shell': ...`, `{ shell }`.
  - `options`: a spread (`...`) inside an object literal in the call's arguments is a finding, and so is a third argument that is not an object literal or a function (so `execFile('git', args, opts)` cannot hide a shell option). Array spreads in the arguments array (`[...SAFE, ...args]`, scripts/handoff-check.mjs) are allowed.
  - `use`: an imported name used other than as a direct call (`const run = execFile`, `promisify(execFile)`, passed as an argument) is a finding.
  - `link`: see Files checked.
- The one exception (the browser start): in the file scripts/smoke.mjs only, one call `spawn(exe,` is accepted with the command `exe`; every other rule still applies to it (no shell, options a literal without a spread). A second such call in that file, or the same call in any other file, is a `command` finding. This copies T-025 fix 2 (one copy per exception), so the exception cannot be reused.
- The checker reads only files; no child process, network, `eval`, `new Function` or `new RegExp` built from file content. Its own source and its test must pass their own rules: the rule patterns are written so their source text holds no `exec(` (for example a character class or a split string), and every bad fixture in the test is joined at run time from pieces. The test's run-directly case uses `execFileSync(process.execPath, [...], { ... })` with no shell, like tests/home-paths.test.js line 180.
- Fixtures: throw-away trees under `resolve(os.tmpdir())` (T-038), removed in `finally`. Links: junctions on Windows; a file or folder symlink that the OS user may not make is skipped with its reason, as in tests/serve.test.js.
- Time: the new test file adds at most 1 s to the unit tests (BACKLOG T-036 (f), the time budget note); one run-directly case starts Node twice at most.
