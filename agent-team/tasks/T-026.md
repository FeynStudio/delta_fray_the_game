## Coordinator choices (technical, not human decisions)
- Unit-test route (recommended, this brief): a new tests/syntax-check.test.js. Nothing is left for the human in a protected file. The other route, a one-word edit by the human to scripts/verify.sh line 42 (`files=(src/*.js tests/*.js sim/*.mjs scripts/*.mjs)`), is listed under "Left for the human" as an alternative; if the human prefers it, this brief is closed without a build.
- What the test does: it walks sim/ on disk (any depth, node_modules skipped), and for every .js and .mjs file runs Node's own syntax check, `node --check <file>`, through node:child_process execFileSync with process.execPath as the program and an argument array; no shell, no command built from text. A file that fails is reported with its path and Node's message. The test also fails if sim/ holds no code file at all (the same "at least one file" rule as verify.sh's lint).
- The walk and the check live in the test file as two small functions. One more test proves them on a throw-away folder in the OS temp dir: a file with a syntax error is reported by name, a clean file is not. Fixture text is built as strings at run time.
- Only sim/ is added. src/*.js, tests/*.js and scripts/*.mjs are already covered by verify.sh's lint; evidence scripts are one-off and stay out.
- The new file holds no comment (checked by the no-comments guard). Plain Node only: node:fs, node:path, node:url, node:os, node:child_process (only to start Node itself), node:test, node:assert. No dependency, no network.
