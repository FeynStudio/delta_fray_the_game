## Goal
A later config tweak cannot make the spawn-protection blink flash faster than 3 times a second without a unit test failing.

## Context

"1. blink is working but make it slower by 1/3 of the speed, 2. title is good but make it 50% larger, 3. explain what is needed, 4. confirm, 5. confirm, 6. confirm, 7. confirm, 8. confirm"

- agent-team/BACKLOG.md T-010 design follow-ups, promote-to-guard idea: "keeps the flash rate at 3 per second or lower (config.protectionBlinkMs >= 334 while protectionMinAlpha is below about 0.5, WCAG 2.3.1)".
- src/render.js protectionAlpha(clockMs): falls linearly from 1 to config.protectionMinAlpha over each config.protectionBlinkMs, then snaps back to 1; one fade-out plus one snap back per cycle, so flashes per second = 1000 / protectionBlinkMs (2.5 at 400 ms, about 1.67 at 600 ms). FEATURE_MAP section 8: tests use node --test, pattern from tests/rules.test.js.

## Coordinator choices (technical, not human decisions)
- The rule: while config.protectionMinAlpha < 0.5 (a deep fade), 1000 / config.protectionBlinkMs must be <= 3, i.e. protectionBlinkMs >= 334 for whole milliseconds. A blink that only dips to 0.5 or above is exempt.
- The test also confirms from protectionAlpha itself that there is exactly one snap back per period (counting rises of more than 0.5 in alpha sampled at 1 ms steps over 10 periods), so the formula matches the drawn curve.
- The check is a small helper in the test file that reads config at call time; overrides are restored in a finally block.
