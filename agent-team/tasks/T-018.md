## Coordinator choices (technical, not human decisions)
- No protected file is edited. scripts/guards.sh and scripts/verify.sh are on the deny list; no human answer lifts it. The owner does not edit them with any tool, shell commands included, and does not work around the deny rule.
- Files:
  - scripts/conflict-markers.mjs (new): the checker. Exports `findMarkers(text)`, returning [{ line, text }] for every marker line, and `checkTree(root)`, returning [{ file, line, text }] for every marker line in the checked files (file paths relative to root, with forward slashes; files in sorted order). Run directly (`node scripts/conflict-markers.mjs`), it checks the repo it lives in: silent and exit 0 when clean; otherwise it prints `GUARD FAIL [no-conflict-markers]: Resolve the merge conflict; never commit conflict markers`, then one `path:line: text` line per finding, and exits 1. Importing the module must not run this command-line part (same isMain pattern as scripts/no-comments.mjs).
  - tests/conflict-markers.test.js (new): node --test, pattern from tests/no-comments.test.js. It holds the checker's own tests and one test that runs checkTree on the real repo root and fails, listing every path:line: text, when anything is found.
- What counts as a marker line: a line that starts (column 1, no leading space) with seven `<`, seven `>` or seven `|` characters, followed by a space or the end of the line. A carriage return before the line feed counts as the end of the line. Eight or more of the character in a row is not a marker. A bare line of seven `=` is not checked on its own (it appears in Markdown and text); every real conflict also has the opening and closing markers.
- Files checked by checkTree: every file under the repo root, at any depth, found by walking the disk (no git call, so untracked files are checked too). Not opened at all:
  - anything named .git (a folder in the main checkout, a file in a worktree) and any node_modules folder;
  - any file named .env or starting with .env. and any folder named secrets (agents may not read them; the checker follows the same rule);
  - symbolic links (not followed);
  - binary files: a file with a zero byte in its first 8000 bytes is skipped, the rule git itself uses, so screenshots in agent-team/evidence/ are not scanned as text.
- Tracked files and evidence must never contain a literal marker at the start of a line. Tests build the marker strings at run time (for example '<'.repeat(7)). The checker's output lines start with path:line, and a saved diff starts each line with a plus, a minus or a space, so saved logs are safe. Do not save a copy of a fixture file. The tree test enforces this on the task's own evidence: if a saved log holds a marker at a line start, the after run fails and the log is saved again in a safe form.
- The two new files hold no comment (AGENTS.md, Non-negotiables; checked by T-023's tree test) and no run of seven `<`, `>` or `|` characters anywhere, also not inside a string.
- Plain Node only: node:fs, node:path, node:url, node:os (temp dir in the test only), node:test, node:assert. No dependency, no network, no child process, no eval, no regular expression built from a variable (semgrep runs in CI with --error; keep to constructs scripts/no-comments.mjs already uses). Keep clear of the JavaScript constructs T-023's tokenizer misreads (listed in the T-023 Handoff, "What the tokenizer does not handle"): the marker test needs no regular expression literal at all.
