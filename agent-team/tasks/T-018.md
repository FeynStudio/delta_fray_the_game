## Coordinator choices (technical, not human decisions)
- New guard "no-conflict-markers" over all tracked files (git grep -nIE, text files only; node_modules is not tracked). Fails on a line that starts with `<<<<<<<`, `>>>>>>>` or `|||||||` followed by a space or the end of the line. A bare `=======` line is not checked on its own (it appears in Markdown and text); every real conflict also has the opening and closing markers.
- Message: "Resolve the merge conflict; never commit conflict markers". The output lists path:line for each hit, like the other guards.
- If git cannot list tracked files (not a repo, git missing), fall back to grep -rnIE over the repo excluding .git and node_modules.
- Test files and evidence must never contain a literal marker at the start of a line: tests build the marker strings at run time (e.g. '<'.repeat(7)). Guard output lines start with path:line, so saved logs are safe; do not save copies of fixture files with markers.
- Tests: tests/guards-conflict.test.js builds throwaway git repos in a temp dir with a copy of scripts/guards.sh and asserts on the `GUARD FAIL [no-conflict-markers]` line only (other guards may fail in the fixture).
