## Coordinator choices (technical, not human decisions)
- One helper, for example `async function withPage(browser, url, size, work)`: opens the page, runs `await work(p)` inside the existing try / finally with the same `failed` flag and the same `.catch` rule, and returns work's value. The three helpers call it and keep only their own work; scoreShot returns scorePixelsProbe's problems from its work and keeps its `if (problems.length) throw ...` after the helper returns, so the order "close, then throw the pixel problems" stays. The name is the owner's, but it must not contain `exec` (guard line 58).
- Behaviour kept exactly: the page is closed on every path; when the work throws, its error reaches the caller unchanged and a close failure goes to stderr as `page close failed after an earlier error: <message>`; when only the close fails, its error reaches the caller; the pages behind the checked results are not touched.
- No other change: no new probe, no change to fixedShot, steadyShot, open(), page.close(), the call sites in FEATURES, or the 20000 ms SEND_TIMEOUT_MS that a close in finally can wait (T-047 security issue 1, noted only).
