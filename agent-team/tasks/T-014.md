## Goal
If the game is ever in the moving phase without a move animation (only reachable through the debug setState), the next step(ms) puts the gauge back to the power phase for the same player and leaves the ships where they are, instead of staying stuck forever.

## Context
Human answer, pasted as-is:
"sending the gauge back to the power phase without moving the ship."

Question as asked: T-003 step(ms) recovery: when step(ms) finds the game in phase 'moving' with no `anim`, what should happen? The coordinator recommended sending the gauge back to the power phase without moving the ship.

- Source: agent-team/BACKLOG.md T-003 item (logged 2026-11-08 in T-003's handoff): a state loaded through __game.setState with gauge.phase 'moving' but no `anim` stays in the moving phase forever. Not reachable through normal play (the second Space always adds anim).
- Current behavior (read 2026-11-09):
  - src/input.js stepMove (lines 100-112): `if (!a || state.gauge.phase !== 'moving' || !(ms > 0)) return state;` so with no anim it does nothing. stepGauge also does nothing in the moving phase, and pressKey ignores Space and Shift while moving.
  - src/game.js step: `const wasMoving = Boolean(state.anim); state = stepMove(stepGauge(state, ms), ms); if (wasMoving && !state.anim) state = endTurn(state);` With no anim, wasMoving is false, so endTurn is not called whatever stepMove returns.
- Paved road: FEATURE_MAP section 4 (stepMove owns the move animation and the return to the power phase; animation state in state.anim), section 8 (pure functions, tests in tests/), section 1/9 (debug API getState/setState/step).

## Coordinator interpretation (not human decisions)
- "the gauge back to the power phase": the gauge becomes exactly `createInitialState().gauge` (power phase, power 0, needle 0, forward, distance 0, sweep 1), the same reset a finished move uses. The locked distance, needle and backward reading are dropped.
- "without moving the ship": every ship (position, heading, alive and any other field) is left exactly as loaded; no move is built from the gauge and resolveMove/applyMove are not called.
- No move happened, so the turn does not pass and endTurn is not called: the same player is on the power gauge. Every other state field (turn, and fields other tasks add such as scores or unmovedSinceSpawn) is unchanged.
- It happens on the first step(ms) with ms > 0, like every other stepMove change (a step of 0 or less changes nothing). Within that step the power gauge does not also sweep; it starts sweeping on the next step.
- Where: in src/input.js stepMove (the pure function that already ends moves), so src/game.js needs no change (wasMoving is false, so endTurn is not called).
