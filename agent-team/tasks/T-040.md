## Coordinator choices (technical, not human decisions)
- Change 1 (30a), one limit in cdp.send: a second constant, `SEND_TIMEOUT_MS = 20000`, named once next to EVAL_TIMEOUT_MS. In `send`, after `ws.send(...)` has returned, the promise stored in `pending` gets a timer: when it fires, the entry is removed from `pending` and the promise rejects with `DevTools message <method> timed out after 20000 ms`; an answer or an error from the browser clears the timer. onmessage is unchanged (a late answer finds no entry and is dropped, as today). 20000 is longer than EVAL_TIMEOUT_MS on purpose: for Runtime.evaluate the page.eval limit fires first and keeps its message that names the probe. The browser-close method keeps its own 3000 ms race; its Browser.close message now also has the 20000 ms timer, which must not delay the end of the run (the main block ends with process.exit).
- Change 2 (30b), page-ready: the arrow function becomes a named probe function `pageReadyProbe(base)` with the same body, placed with the other probes. page.eval marks its own time-out error (a property set on the Error object, not Object.assign, not a match on the message text). The loop's catch returns false for any other error, as today (errors while the page navigates must still be retried), and rethrows a marked time-out at once, so the run fails with `page evaluation timed out after 15000 ms in pageReadyProbe`. The deadline and its message are unchanged.
- Change 3 (30d), page.eval order: the Runtime.evaluate message is built and sent first; only then is the timer made and the race set up, in the same synchronous step. So an error thrown while building or sending the message (for example an argument JSON.stringify cannot handle) leaves no timer behind and reaches the caller as a normal rejection.
- Parts of scripts/smoke.mjs this task may change: the constants block (one new constant), `send` inside connect, page.eval, the page-ready loop inside open, and the new pageReadyProbe function. Everything else stays byte for byte: the imports, findBrowser, the WebSocket creation, onmessage, `ready` and `close` in connect, launchBrowser's spawn call and flags, the port file and address code (the scanner directive line included), the other set-up lines of open, key, screenshot, the page close(), the browser close method, every other probe, stateShot, phaseShot, FEATURES and its result keys, the main block, and scripts/serve.mjs.

- Hangs are not reproduced on BASE on purpose (a hung run must be killed from outside and can leave a headless browser and its profile behind). The gaps of (30a) and (30d) are shown by reading on BASE; the fixes are shown with scratch changes on the committed change. (30b) on BASE ends by itself at the loop's deadline, so it is run.
