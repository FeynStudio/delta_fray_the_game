## Coordinator choices (technical, not human decisions)
- No protected file is edited. scripts/verify.sh and scripts/guards.sh are on the deny list; no human answer lifts it. The owner does not edit them with any tool, shell commands included, and does not work around the deny rule.
- Files:
  - scripts/handoff-check.mjs (new): the check. Exports:
    - `taskFromBranch(name)`: 'T-###' for a branch named task/T-###-anything or task/T-### (three or more digits), otherwise null.
    - `checkHandoff(root, task)`: returns { result: 'PASS' | 'FAIL' | 'SKIP', reason, commit, subject } for the repo at root. task is 'T-###', 'T-###-review' (uses brief T-###) or null.
    - Run directly, `node scripts/handoff-check.mjs [TASK]` checks the repo it lives in; with no argument the task is read from the current branch. It prints exactly one result line: `PASS handoff names the latest code commit`, `FAIL handoff names the latest code commit` (followed by one line `Handoff does not name <C>; latest code commit is <C> (<subject>)`) or `SKIP handoff check (<reason>)`. Exit 1 on FAIL, exit 0 on PASS and on SKIP. Importing the module must not run this command-line part (same isMain pattern as scripts/no-comments.mjs).
  - tests/handoff-check.test.js (new): node --test, pattern from tests/no-comments.test.js. It holds the module's own tests on throw-away git repos, and one test named for the real repo that calls checkHandoff(ROOT, taskFromBranch(current branch)): it passes on PASS, fails with the FAIL message (naming C and its subject) on FAIL, and is reported as skipped with the reason on SKIP.
- The check applies only when all of these hold; otherwise the result is SKIP with the reason, which never fails anything:
  1. There is a task: the branch is a task branch (or TASK was given by hand and starts with T-###), and the brief agent-team/tasks/T-###.md exists in the working tree. A detached HEAD (CI) and master have no task.
  2. The brief's "## Handoff" section (from that heading to the next "## " heading or the end of the file) has text other than the "(owner fills in)" placeholder.
  3. The brief's top Status line is not DONE (closed briefs are a record; merges are noted by the coordinator).
  A folder that is not a git repo, or a machine where git cannot be run, also gives SKIP with that reason.
- Code commit C: walk back from HEAD along first parents; C is the first commit whose diff against its first parent (for the root commit: against the empty tree) touches any path outside agent-team/. A merge that brings in code counts, which covers the "run on a merge commit" case. The check passes if the Handoff section contains the first 7 characters of C's hash; otherwise FAIL. The brief is read from the working tree, so a handoff edit that is not committed yet counts.
- "Evidence newer than the handoff" is covered through C (evidence runs on newer code mean a newer C); no separate evidence-file rule.
- Working rule that follows from the check (goes into the FEATURE_MAP line): after a new code commit on a task whose Handoff is already filled in, update the Handoff to name the new commit first (saving the file is enough), then run verify.sh. A task that changes nothing outside agent-team/ names the commit the FAIL message gives, which is the code it was checked against.
- git is called through node:child_process execFileSync with the fixed command name 'git', an argument array and cwd set to the repo; no shell, no command built from text. scripts/smoke.mjs already imports node:child_process (spawn) and passes the CI scan. Only read commands are run on the real repo (for example rev-parse, rev-list, diff-tree, log, branch --show-current); nothing that changes the repo, its index or its configuration.
- Fixture repos: made with `git init` in the OS temp dir and removed afterwards. Fixture commits give their own user name and email on the command line (`-c user.name=... -c user.email=...`, signing off) and never change git configuration outside the fixture. The merge fixture is made inside the fixture repo only, by the test; the owner never runs git merge by hand in the product repo or a worktree (deny list).
- The two new files hold no comment (AGENTS.md, Non-negotiables; checked by T-023's tree test). Fixture briefs are built as strings at run time. Keep clear of the JavaScript constructs T-023's tokenizer misreads (T-023 Handoff, "What the tokenizer does not handle").
- Plain Node only: node:fs, node:path, node:url, node:os (temp dir in the test only), node:child_process (git only), node:test, node:assert. No dependency, no network, no eval, no regular expression built from a variable.
