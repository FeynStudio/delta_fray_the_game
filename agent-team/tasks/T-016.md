## Goal
A reviewer running verify.sh on a task gets a FAIL when the brief's Handoff still describes an older commit than the code actually under review, so stale handoff text is caught by the tool instead of by eye.

## Coordinator choices (technical, not human decisions)
- The check ("handoff names the latest code commit") runs in verify.sh right after guards, for every feature. It applies only when all of these hold; otherwise it prints `SKIP handoff check (<reason>)` and does not fail:
  1. TASK starts with T-### (e.g. T-016 or T-016-review); the brief is agent-team/tasks/T-###.md and exists.
  2. The brief's "## Handoff" section has text other than the "(owner fills in)" placeholder.
  3. The brief's top Status line is not DONE (closed briefs are a record; merges are noted by the coordinator).
- Code commit C: walk back from HEAD along first parents; C is the first commit whose diff against its first parent touches any path outside agent-team/ (a merge that brings in code counts, which covers the "run on a merge commit" case). The check passes if the Handoff section contains the first 7 characters of C; else `FAIL handoff names the latest code commit` with a log line "Handoff does not name <C>; latest code commit is <C> (<subject>)".
- "Evidence newer than the handoff" is covered through C (evidence runs on newer code mean a newer C); no separate evidence-file rule.
- Tests: tests/verify-handoff.test.js builds throwaway git repos in a temp dir, copies scripts/verify.sh into them with a stub scripts/guards.sh (`exit 0`) and no tests/ folder (so verify.sh never runs the real unit tests again: no recursion), runs `bash scripts/verify.sh <TASK> --feature config` and asserts only on the handoff check's PASS/FAIL/SKIP line (the other checks fail in the fixture by design).
