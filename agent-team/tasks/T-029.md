## Coordinator choices (technical, not human decisions)
- Fix A, long history (reviewer issue 1). The walk must not depend on one output fitting in 1 MiB. Recommended way: read the first-parent history in pages (`rev-list --first-parent --parents -n <page> --skip=<done> HEAD`, the page size named once in the module) and stop at the first code commit, so no single output can reach the limit at any history length. Raising `maxBuffer` alone only moves the limit and is not accepted on its own. The rule for C does not change.
- Fix B, one filter for the branch read (reviewer issue 2, security issue 3). The real-repo test gets the branch name from the module, through the same filtered helper the check uses (export the existing `currentBranch(root)`; it becomes the module's fourth export). The test's own unfiltered git call is removed.
- Fix C, tests for what T-016 added beyond its brief (reviewer issue 3). One fixture each, in its own throw-away repo: a subfolder of a fixture repo gives SKIP 'not the top folder of a git repo'; a repo whose only commits touch agent-team/ gives SKIP 'no commit touches a path outside agent-team/'; a fixture repo with a filled-in brief and no commit yet gives SKIP 'git history cannot be read'. And one test for the filter: with GIT_DIR and GIT_WORK_TREE set in the test process's own environment to a second fixture repo, `checkHandoff(root, ...)` and the branch read both still answer for the repo at root. That test changes process.env, so it must not run side by side with any other test (put it outside the concurrent describe) and it restores the two variables in a `finally`. 'git cannot be run' is tested only if it can be done without changing PATH for other tests; otherwise the Handoff says it has no test.
- Fix D, hardening (security issue 1). Every git call of the module starts with `-c core.fsmonitor=false`; the log call carries `--no-show-signature`. Both go into the one helper or the one call, as fixed literal arguments.
- Fix E, control characters (security issue 2). The subject is cleaned before it is stored in the outcome: every code point U+0000 to U+001F, U+007F and U+0080 to U+009F is removed; other text is kept as it is. So `outcome.subject`, `outcome.reason`, the command-line output and the test's assertion message hold no escape sequence.
- Fix F, the "not a git repo" test (security issue 5). The test passes wherever the OS temp dir is. It still pins the reason 'not a git repo' when the temp dir is not inside a git repo; when it is, it expects 'not the top folder of a git repo'. How the test finds out is the owner's choice.
- Optional, only if it is cheap (reviewer issue 4, one git process per commit walked): fewer git processes for the walk, for example one process that reads several commits. Do it only if the existing merge-commit and root-commit tests pass unchanged and the change fits the size limit; otherwise leave it and say so in the Handoff. It is not a Done-when item.
- Not changed, on purpose: the rule for C; the conditions under which the check applies; the PASS, FAIL and SKIP line wording; the existing SKIP reasons (none added, none removed); `taskFromBranch`, `checkHandoff` and `report` signatures; that a git error gives SKIP (T-016's design: "a machine where git cannot be run also gives SKIP"). Security review Issue 4 (fixture reads go through the user's global git configuration, read only) is not part of this brief; it is logged in BACKLOG.
- Evidence fixtures for Done-when 2 and 3 are made by a comment-free one-off script agent-team/evidence/T-029/gaps.mjs, in the OS temp dir, and removed by the script. It may use git commands that write, inside its fixture repos only (for example one `git fast-import` process to build 14,000 commits quickly). Fixture commits give their own user name and email on the command line, as the T-016 tests do, and use an empty global configuration file inside the fixture folder.
- The fsmonitor reproduction (Done-when 2e and 3e) sets `core.fsmonitor` in the fixture repo's own .git/config to a command that only creates a marker file inside the fixture folder. It is the security reviewer's reproduction, repeated; nothing outside the fixture folder is run or written. If it cannot be reproduced on the owner's machine, the Handoff says so and item 3e is shown by reading (the grep in Done-when 6).
