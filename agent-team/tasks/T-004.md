# T-004 Hits and edges: rules.resolveMove destroys swept enemies and ships that reach the wall (Prototype 1, slice 4; first half of the turns request)
Status: READY
Owner role: Owner
Created: 2026-11-09
Verify feature: hits  (passed as --feature to every verify.sh run for this task)

## Goal
After a move, the rules know which ships are destroyed: an enemy anywhere inside the area the moving ship swept is destroyed, and a moving ship that reaches a map edge is destroyed (both, if it hits an enemy and then the edge).

## Context
Request from the human, pasted as-is:
"work on building the turn slice that adds the taking-turn mechanism"

- Why this brief exists: the turns check cannot pass without hit detection. Every case in scenarios/turns.json calls `resolveMove` before `endTurn`, and `./scripts/verify.sh --feature turns` on master fails with "src/rules.js does not export resolveMove()". resolveMove is the hits slice (FEATURE_MAP section 5), which comes before respawn in the docs/DESIGN.md build order ("movement, hit detection + edges, respawn") and has not been built yet. The request is therefore split in two: this brief (T-004, hits, goes first) and T-005 (turns: endTurn and the turn manager in game.js), which starts after T-004 is merged.
- Starting point: product-a master after T-003 (movement) and the smoke.mjs fix ef1704e. Branch: task/T-004-hits.
- Feature map: agent-team/FEATURE_MAP.md section 5 (Hit Detection & Edges, including its Known traps), section 8 (paved roads: new rule = pure function in src/rules.js plus a test in tests/ in the rules.test.js pattern), section 9 (harness contract: `resolveMove(state, move)`: "applyMove plus swept-area hits and walls; destroyed ships get alive: false. No respawn, no turn change.").
- Spec for the check: scenarios/hits.json and expected/hits.json, run by scripts/run-scenario.mjs (inputs deep-frozen, numbers rounded to 3 decimals). Do not edit them. The scenario states have no `gauge` field, and the scenario overrides shipSize 30 but not shipWidth, so the default shipWidth 16 applies.
- Design: docs/DESIGN.md and docs/PLAN.md "Rules": enemy inside the swept path is destroyed, any part counts; reaching a map edge destroys the moving ship; hitting an enemy and then the edge destroys both; edges are solid (no wraparound). DESIGN.md "Workflow": hit detection and edge logic must have unit tests, including grazing contact, hit-then-wall and max-distance moves.
- Ship shape: the human decision of 2026-11-08 (agent-team/DECISIONS.md) made ships a slim triangle: config.shipSize 30 = long side, config.shipWidth 16 = back edge, centroid at the ship position (src/render.js `shipPoints`). BACKLOG (T-001 line, 2026-11-08) says hit detection must use this same shape from config, not an equilateral one. scripts/guards.sh only lets src/rules.js import ./config.js, so rules.js cannot import render.js.
- `--feature hits` has no browser step. `--feature config` (scenarios/config-override.json) also needs resolveMove, so it can pass for the first time in this task.
