# T-004 Hits and edges: rules.resolveMove destroys swept enemies and ships that reach the wall (Prototype 1, slice 4; first half of the turns request)

## Goal
After a move, the rules know which ships are destroyed: an enemy anywhere inside the area the moving ship swept is destroyed, and a moving ship that reaches a map edge is destroyed (both, if it hits an enemy and then the edge).

## Context

- Owner choices (the brief left these open):
  - The swept area is the convex hull of the mover's start and end triangles, both drawn in the heading the ship ends with. This matches input.startMove, which turns the ship before it moves. A forward move that turns therefore does not count the old-heading triangle at the start position. tests/hits.test.js covers this with "the swept triangle uses the heading the ship turns to as the move starts".
  - Overlap uses the separating axis test, and touching counts. A 1e-9 game-unit slack (`TOUCH` in rules.js) keeps exact contacts from failing on floating-point rounding. It is a numerical tolerance, not a game size, so it is not in config.
  - Wall: the mover dies if any hull corner has x <= 0, y <= 0, x >= worldWidth or y >= worldHeight (within TOUCH). Because the hull is convex, its corners give its full extent.
  - A destroyed mover keeps its applyMove position (no clamping). An enemy that is already `alive: false` is left as it is. A refused move returns the same state object.
- Not verified:
  - On screen: src/game.js still uses applyMove (T-005 scope), so no ship is destroyed in the running game, and I did no human-eye browser check of hits.
  - The case where the mover's start triangle already overlaps an enemy before the move and the mover turns away. That enemy survives under the owner choice above, and no scenario covers it.
