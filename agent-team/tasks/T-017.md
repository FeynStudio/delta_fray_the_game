## Coordinator choices (technical, not human decisions)
- Decision on expected/: not needed. The new captures follow the phaseShot pattern (fail by throwing an error that names the file) and add no keys to the turns result, so expected/turns-smoke.json stays unchanged. Adding a named result key would need an expected/ change and the Approval gate above.
- Captures go under the existing `turns` feature (it already runs a move and a kill), each in its own page opened after the checked turns page is done, so the existing results are unaffected.
- Backward launch setup: player 1 off its spawn (not protected, clear of walls and the enemy), power locked, Shift pressed, needle set to a non-zero value (e.g. 30) so the travel angle differs from heading + 180.
- Explosion capture: a kill as in turnsProbe, then step to the end of the move and on to about half of config.explosionMs (not elapsed 0, which looks like an intact ship; BACKLOG T-012 observation).
